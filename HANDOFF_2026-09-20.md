## Configuration

The root `.env` is active and intentionally excluded by `.gitignore`. It now
contains configuration for:

- Supabase project URL and server-side secret key;
- `SDOC_STORE=supabase`;
- local SQLite fallback path;
- organizer bundle path;
- waiting and timer intervals;
- CORS origins;
- comma-separated `GEMINI_KEYS`;
- `GEMINI_MODEL=gemini-3.1-flash-lite`.

Never expose `SUPABASE_SECRET_KEY` or Gemini keys in browser code or commits.
`.env.example` documents the expected variable names without real values.

## Common commands

Run from `C:\Documents\SDOC\Averis1am`:

```powershell
# Start the Supabase-backed API and both dashboards
python run_api.py

# Re-ingest the advanced PDF demo with OCR and independent verification
python scripts/ingest_source.py demo-data --ocr --verify

# Validate the local demo fixtures
python scripts/validate_demo_data.py demo-data --db data/sdoc.db

# Run the full regression suite
python -m pytest -q
```

Ingestion is idempotent by email ID. Re-running it will not duplicate cases or
document versions.

## Remaining boundaries / recommended next work

1. Add Gmail or Outlook ingestion only when mailbox credentials and the desired
   provider are available. Email sending should remain human-approved by default.
2. Add authentication, organization membership, and role-based access before a
   shared or public deployment.
3. Expand human review from a resolution note into structured field corrections
   that rerun comparison and retain before/after evidence.
4. Add production hosting, secret management, monitoring, and retention policy.
5. Benchmark the chosen Gemini model and quotas on a larger representative set
   before relying on automation-rate or quality claims beyond the demo.
