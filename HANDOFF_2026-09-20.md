## Work completed this session

### Defects fixed

- **Attachment path traversal.** The Gmail write path built its destination
  from the untrusted MIME filename with no containment, so a crafted name
  resolved outside the attachment root and into the source directory. The
  serve path in `api.py` was already correctly defended; `safe_filename` is
  the matching guard on write.
- **Silent verifier truncation.** Document text was cut at 50,000 characters
  with no signal, making a field that was never read indistinguishable from
  one the document lacks. Oversized text now raises `TruncatedDocumentError`,
  which fails verification into human review.
- **Supabase comparison shape.** The hosted store returned comparisons under
  `evidence_json` while the worker dashboard reads `evidence`, so the
  seven-field evidence table never rendered against Supabase. Both stores now
  return the same shape.

### Source-traceable extraction (v2 §6.3, P0)

Every consumer of source evidence already existed end to end — `docs`,
`compare`, `app.js`, the evidence viewer — but no reader produced any, so the
viewer always fell back to "no box stored yet".

Readers now emit pairs carrying provenance:

| Format | Evidence |
|---|---|
| PDF | page, bounding box in points, page dimensions, snippet |
| Text, OCR | line, page, snippet |
| docx, xlsx | table or sheet, row, snippet |

Plain `(label, value)` tuples are still accepted from third-party readers. The
evidence viewer places its overlay from real coordinates as a share of the
page, and states plainly when placement is unavailable.

### Validation statuses and bounded recovery (v2 §7.2–7.4, P0)

`sdoc/validation.py` checks structure — required fields present and parseable
under their canonical kind — and on failure runs **one** recovery cycle that
must change something: the specific failures are fed back to the extractor, or
a PDF is re-read through OCR as an alternate route.

Outcomes are `FIRST_PASS_VALIDATED`, `RECOVERED` or `NEEDS_REVIEW`, each with
a trace of what the retry did. These describe the extraction, not the case,
and do not affect the submission contract.

### Correct Extraction (v2 §9, P1)

The worker action that v2 Table 18's demo row depends on. A reviewer replaces
a wrongly extracted value; the previous value is kept and the case is
re-decided.

- `compare_values` is split out of `compare_documents` so a correction runs
  the same rules as the automated path.
- `apply_correction` is shared by both stores so SQLite and Supabase cannot
  drift.
- New `field_corrections` table, `POST /api/cases/{id}/correct`, and an inline
  editor in the comparison table.

Verified on real organizer data: correcting `consignee` on email_004 leaves
`notify_party` outstanding; correcting both clears the case to VERIFIED and
closes its review task.

### Preflight security and resource gate (Addendum A3)

Attachments pass a gate before any model call, checked in increasing cost
because parsing is itself the attack surface: byte length, then magic bytes,
then structure.

Rejections: oversize, declared-versus-actual type mismatch, page count,
encrypted, malformed, OOXML expansion, attachment count. A gated message
reaches no reader and becomes a `BLOCKED` action — no new case state was
needed.

The organizer contract fixes `review_reason` to `wrong_doc_type |
missing_attachment | unreadable | missing_value`, so a gated document reports
`unreadable` and the specific reason stays in evidence.

### Spend ceilings (Addendum A3)

`sdoc/budget.py` bounds horizontal amplification, which a per-case budget
cannot: many individually compliant messages still add up. Per-sender and
global daily ceilings persist to disk, so a restart does not reset an
attacker's allowance. Wired into the Gmail sync loop, where untrusted mail
actually arrives.

## Configuration

New environment variables, all optional with working defaults:

| Variable | Default | Purpose |
|---|---:|---|
| `SDOC_MAX_ATTACHMENT_BYTES` | 26214400 | Per-attachment size ceiling |
| `SDOC_MAX_PAGES` | 200 | Page ceiling before `BLOCKED` |
| `SDOC_MAX_ATTACHMENTS` | 20 | Attachments per message |
| `SDOC_MAX_EXPANSION` | 200 | OOXML decompression ratio |
| `SDOC_MAX_ARCHIVE_ENTRIES` | 2000 | Entries inside an OOXML archive |
| `SDOC_MAX_PER_SENDER_DAY` | 200 | Messages per sender per UTC day |
| `SDOC_MAX_MESSAGES_DAY` | 2000 | Messages per UTC day, all senders |
| `SDOC_VERIFIER_TEXT_LIMIT` | 50000 | Above this, verification fails loudly |
| `SDOC_BUDGET_PATH` | data/spend_ledger.json | Spend ledger location |

`.env` is git-ignored, as are `gmail_token.json`, `gmail_state.json`,
`spend_ledger.json` and the synced attachments. Never expose
`SUPABASE_SECRET_KEY` or Gemini keys in browser code or commits.

## Remaining work

Ranked by value, from the priorities in v2 §15 and Addendum A7.

1. **Full-page coverage (A1) and aggregate calculation (A2).** Designed, not
   built. Near-zero demo value while every document in the corpus is a single
   page; required before any genuinely multi-page document is trusted.
2. **Select Correct Version / Pairing**, and Escalate, to complete the v2 §9
   action set. Review resolution for pairing is still a note.
3. **Admin quality metrics** — discrepancy precision and recall, per-field
   extraction accuracy, classification accuracy, latency, first-pass and
   recovery rates. The organizer set carries the ground truth needed.
4. **Authentication, tenancy, RBAC.** P2 in v2 §15, explicitly beyond the
   hackathon MVP; all endpoints are currently unauthenticated.
5. **Sandboxed parsing and malware scanning.** Deferred deployment controls;
   parsing currently runs in-process.
6. **Gate signals into classification.** A declared type that disagrees with
   the actual type is a useful malicious-mail signal, but it is not strong
   enough to decide a category alone, and wiring it would reorder
   classification after the gate. Not done; the value is marginal on this
   corpus.
7. `includeSpamTrash` on the Gmail fetch, so the SPAM category is exercised on
   live mail rather than only on organizer fixtures.
